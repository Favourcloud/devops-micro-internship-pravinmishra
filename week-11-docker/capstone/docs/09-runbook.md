# EpicBook operator runbook

1. **Start:** connect with the pinned SSH host key; enter `/opt/week11/capstone`; verify private secret files exist without printing them; run `docker compose config --quiet`, then `docker compose up -d --wait --wait-timeout 180`. Confirm four healthy services and a catalogue response from the public HTTPS URL.
2. **Inspect:** check `docker compose ps`, bounded JSON logs, disk space and `/health` from inside the backend. Distinguish running, healthy and user-visible availability. Docker does not heal a stopped dependency automatically merely because depends_on is configured.
3. **Release:** back up the database before schema changes, build from reviewed source/locks, retain the previous image ID, run `docker compose up -d --wait`, then test catalogue, signed cart, synthetic checkout and independent SQL. Revert to the retained prior image if application checks fail; do not roll back a schema blindly.
4. **Stop:** use `docker compose stop` for maintenance. Data and logs remain. Do not remove named volumes. The user asked that the demos remain online until cleanup is explicitly requested.
5. **Rotate credentials:** schedule maintenance and back up first. Rotate the MySQL application password with the database administrator, update its protected file, recreate backend, and verify access. Updating MYSQL_PASSWORD_FILE alone does not change an already-initialized database user. Rotate the root account separately. Changing the session key invalidates signed carts; communicate this before rotation. Never put secret values in a shell transcript, image or Git commit.
6. **Disaster recovery:** provision a clean host, restore the exact database image/version and snapshot into a new volume, restore protected secret material separately, inspect it on an isolated network, compare counts and order rows, then switch the reviewed Compose configuration to that volume. Test HTTP/SQL and preserve the old volume until recovery is accepted. A local backup alone cannot survive a host/disk loss; retain a verified off-host copy.
7. **Capacity and logs:** watch the 40 GB disk and memory. Rotate bind-mounted Nginx logs on the host and reload Nginx; Docker's container logs already have size/count limits. Do not prune unrelated user images or volumes. Backups and the stopped restore volume are intentionally retained for inspection.
8. **Cleanup:** only after the learner requests it, export the desired evidence/backups, review a Terraform destroy plan scoped to this Week 11 state, and remove only the approved Week 11 resources. Never apply cleanup to older retained demos.

### Remaining limit: versioned tag vs. immutable digest

The image check passes but carries this note: **`(mutable; digest preferred)`**. A tag like `:1.0.0` is a human-readable pointer in the registry — it can be repointed to a different image layer without warning. An immutable digest (`sha256:…`) is a cryptographic hash of the exact image manifest; it cannot change. For production or supply-chain-sensitive deployments the Dockerfile `FROM` line should pin to a digest:

```dockerfile
# Mutable tag — passes this audit but still rebindable
FROM node:20-alpine3.19

# Immutable digest — strongest guarantee
FROM node:20-alpine3.19@sha256:<full-digest-here>
```

For the application image itself the Compose `image:` field or a private registry tag should similarly be frozen by digest if reproducibility is required.
